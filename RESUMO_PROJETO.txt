STACK
-----
- Backend  : ASP.NET Core .NET 8 — porta HTTPS 7039 / HTTP 5247
- Frontend : Blazor WebAssembly .NET 8 + MudBlazor 9.4.0 — HTTPS 7252 / HTTP 5197

FUNCIONALIDADE DE DESCONTO (implementada nesta sessão)
------------------------------------------------------
- Campo DiscountAmount (decimal, default 0) na entidade Order e na tabela Orders
- PDV: campo "Desconto (R$)" no resumo antes de finalizar; refletido no Total em tempo real
- Pedidos: seção "Aplicar Desconto" no dialog de detalhes (edição pós-criação)
- Endpoint: PATCH /api/pedido/{id}/desconto { DiscountAmount }
- Cálculo: AmountWithSurchargeTotal = (AmountTotal × fator) − DiscountAmount
- Recibo: linha "Desconto" mostra o valor real; TOTAL reflete o desconto

RECIBO DE IMPRESSÃO — ESTADO ATUAL
------------------------------------
JS printRecibo(html) em index.html: window.open + doc.write + setTimeout(400ms) + print()
- Cabeçalho: nº pedido, data, dados completos do cliente, forma de pagamento
- Itens (2 linhas por div):
    Linha 1: #N [CODIGO] Nome (esquerda, truncado com "…")
    Linha 2: qtd × R$ unitário_com_acréscimo = R$ total (direita)
- Totais: Subtotal | Desconto | TOTAL
- Acréscimo embutido no preço unitário — não exibido como linha separada

GESTÃO DE USUÁRIOS — ESTADO ATUAL
-----------------------------------
- Senha criptografada: PBKDF2 via ASP.NET Identity (nunca armazenada em plain text)
- Admin NÃO consegue ver a senha de outro usuário; pode apenas redefini-la
- Endpoint alterar senha: PATCH /api/user/{id}/senha { NewPassword }
  → Usa GeneratePasswordResetTokenAsync + ResetPasswordAsync (sem exigir senha atual)
- Usuarios.razor: ícone 🔒 (amarelo) em cada linha → dialog "Alterar Senha — [Nome]"
  - Campos: Nova Senha + Confirmar (validação de igualdade)
  - Alerta informativo sobre criptografia exibido no dialog
- Regras de senha exibidas visivelmente nos dialogs de criação e de alteração:
    • Mínimo 6 caracteres
    • Pelo menos uma letra minúscula (a-z)
    • Pelo menos um número (0-9)
- Validação client-side em ValidarSenha() verifica as mesmas 3 regras antes de chamar a API

INFRAESTRUTURA DE IMPRESSÃO — API (100% PRONTA)
------------------------------------------------
PrintHub.cs: ?agentKey=xxx → grupo "PrintAgents"; demais → grupo "Clients"
PrintJobController:
  GET  /api/printjob/pendentes        (X-Agent-Key)
  PATCH /api/printjob/{id}/status     (X-Agent-Key) + notifica "Clients" via SignalR
  GET  /api/printjob/{jobId}/order    (X-Agent-Key) — retorna OrderResponseDto completo
  GET  /api/printjob                  (JWT Admin)
PedidoController.Finalizar: cria PrintJob OnHoldem → SignalR "NewPrintJob" {printJobId}
Chave do agente: em appsettings.Development.json → PrintAgent:AgentKey

FLUXO DO PRINT AGENT (app Windows — ainda não implementado)
------------------------------------------------------------
1. PDV finaliza → API cria PrintJob (OnHoldem) → SignalR "NewPrintJob" {jobId}
2. PrintAgent recebe → GET /api/printjob/{jobId}/order
3. Formata recibo → imprime via System.Drawing.Printing (Windows GDI+)
4. PATCH /api/printjob/{jobId}/status → Printed
5. API notifica Blazor via "PrintJobStatusChanged"
Failsafe: ao iniciar, consulta GET /pendentes e processa jobs perdidos
Instalação: New-Service + Start-Service (ver instruções no chat)
