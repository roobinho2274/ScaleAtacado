MULTI-PAGAMENTO COM VALOR POR FORMA (feature completa — implementada)
-----------------------------------------------------------------------
Conceito:
  - À Vista (IsInstallment=false): 1 ou mais formas de pagamento por pedido
    • 1 forma selecionada → aplica SurchargePercentage desta forma; Amount = total do pedido (auto)
    • 2+ formas → SurchargePercentage = 0; usuário informa o valor pago em cada forma
  - A Prazo (IsInstallment=true): exatamente 1 forma de pagamento; Amount = total do pedido (auto)

Validação servidor (OrderAppService):
  - dto.Payments.Count > 1: valida |sum(Amount) - totalFinal| <= 0.01
  - dto.Payments.Count == 1: ignora Amount recebido; grava totalFinal diretamente
  - Mensagem de erro: "A soma dos valores de pagamento (R$ X) não corresponde ao total do pedido (R$ Y)."

Validação cliente (PDV.razor / Pedidos.razor):
  - Mostra "Restante: R$ X" em verde se ok, vermelho se diferença
  - PDV: botão FINALIZAR bloqueado se _hasPaymentSelected mas multi e soma errada
  - Pedidos: botão "Alterar Pagamento" mostra snackbar de aviso se soma errada, aborta

Armazenamento:
  - OrderPaymentMethod.Amount: decimal, coluna numeric(18,2), DEFAULT 0

Exibição (Pedidos.razor - detalhe do pedido):
  - 1 forma: exibe só o nome
  - 2+ formas: cada linha "Nome: R$ X,XX"

CÓDIGO DE USUÁRIO (UserCode)
------------------------------
- Cada usuário tem um código numérico único de 4 dígitos (1000–9999), global (não por empresa)
- Global para evitar conflito no login: na hora do login, a empresa ainda não é conhecida
- Gerado automaticamente ao criar usuário; pode ser regenerado via UI ou API
- Login: se dto.Login tem exatamente 4 dígitos numéricos → busca por UserCode; senão busca por e-mail
- Mensagem de erro unificada: "E-mail, código ou senha inválidos."

ERROS COMUNS E SOLUÇÕES
------------------------
- 401: token expirado → logout + login
- "Sistema já configurado": DELETE FROM "Companies"; (não basta apagar AspNetUsers)
- 400 sem mensagem: pode ser FluentValidation (ValidationProblemDetails, não ApiResponse)
- 500 ao criar pedido: migration pendente → dotnet ef database update
- Auditoria vazia: reiniciar API após correção do filtro de data (AddDays(1) + SpecifyKind Utc)
- MudSelect MultiSelection: SelectedValuesChanged requer tipo explícito na lambda
  ex: (IReadOnlyCollection<T> vals) => { _field = vals; StateHasChanged(); }
- MudButtonGroup: não tem atributo DisableElevation (MudBlazor 9 — remover se houver)
- "Application" ambíguo no PrintAgent: usar alias WinForms = System.Windows.Forms
- Locks de DLL ao buildar: fechar processo ScaleAtacado.Api antes de dotnet build/ef migrations
- psql no PowerShell: aspas duplas em SQL não passam corretamente;
  usar docker exec com Bash ou arquivo .sql com -f
