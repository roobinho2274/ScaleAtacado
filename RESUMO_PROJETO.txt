STACK
-----
- Backend  : ASP.NET Core .NET 8 — HTTPS 7039 / HTTP 5247
- Frontend : Blazor WebAssembly .NET 8 + MudBlazor 9.4.0 — HTTPS 7252 / HTTP 5197
- Banco    : PostgreSQL 15 (Docker, container: scale_atacado_db, porta 5432)
- ORM      : Entity Framework Core
- Auth     : JWT (Bearer) — token em sessionStorage (expira ao fechar o browser/aba)
- Impressão: SignalR PrintHub + PrintAgent Windows (EPSON TM-T20X) — fluxo completo implementado

FUNCIONALIDADE DE DESCONTO
---------------------------
- Campo DiscountAmount (decimal, default 0) em Order e na tabela Orders (migration AddDiscountToOrder)
- PDV: campo "Desconto (R$)" no resumo; total atualiza em tempo real
- Pedidos: seção "Aplicar Desconto" no dialog de detalhes (edição pós-criação)
- Endpoint: PATCH /api/order/{id}/discount { DiscountAmount }
- Cálculo: AmountWithSurchargeTotal = (AmountTotal × fator) − DiscountAmount

ALTERAÇÃO DE FORMA DE PAGAMENTO EM PEDIDOS (Admin)
---------------------------------------------------
- Admin pode alterar a forma de pagamento de um pedido existente no dialog de detalhes
- PATCH /api/order/{id}/payment (AdminOnly) — recebe { PaymentMethodId }
- OrderAppService.UpdatePaymentMethodAsync:
    1. Busca pedido e nova forma de pagamento (valida se ativa)
    2. order.PaymentMethodId = novo id
    3. surcharge = AmountTotal × (newPaymentMethod.SurchargePercentage / 100)
    4. AmountWithSurchargeTotal = AmountTotal + surcharge − DiscountAmount
    5. Grava + audita com operation "ChangePaymentMethod"
- Blazor (Pedidos.razor):
    • PaymentMethodService injetado; lista carregada em OnInitializedAsync
    • Campo _editPaymentMethodId inicializado com o PaymentMethodId do pedido ao abrir dialog
    • Botão "Alterar Pagamento" desabilitado se selecionado == atual
    • Ao salvar: chama OrderService.UpdatePaymentMethodAsync → recarrega pedido
- SurchargePercentage vem do OrderResponseDto (calculado ao buscar, não armazenado na tabela)

EXIBIÇÃO DE PREÇOS COM ACRÉSCIMO (Pedidos.razor — dialog de detalhes)
-----------------------------------------------------------------------
- UnitPrice e TotalPrice nos OrderItems são armazenados sem acréscimo (preço base)
- Ao exibir no dialog, multiplica pelo _surchargeRate para mostrar valor real ao cliente:
    var _surchargeRate = 1 + _orderDetail.SurchargePercentage / 100m;
    // na coluna Unitário:  (context.UnitPrice  * _surchargeRate).ToString("N2")
    // na coluna Subtotal:  (context.TotalPrice * _surchargeRate).ToString("N2")
- Rodapé exibido quando SurchargePercentage > 0:
    "* Preços exibidos com acréscimo de X% (NomeForma) já incluído."
- AmountWithSurchargeTotal (o total final correto) é mostrado diretamente do DTO — já está correto

RECIBO DE IMPRESSÃO
--------------------
FLUXO (unificado com PrintAgent):
  1. Usuário clica "Imprimir Recibo" no dialog de detalhes do pedido
  2. Pedidos.razor abre MudDialog com <iframe srcdoc="..."> mostrando prévia HTML
  3. Usuário clica "Confirmar Impressão" → POST /api/order/{id}/printjob → cria PrintJob
  4. API dispara SignalR "NewPrintJob" {printJobId} ao grupo "PrintAgents"
  5. PrintAgent recebe → GET /api/printjob/{id}/order → formata → imprime fisicamente
  6. PrintAgent → PATCH /api/printjob/{id}/status → Printed

PRÉVIA HTML (BuildReceiptHtml — Pedidos.razor):
- MudDialog nativo (sem popup/window.open); iframe com srcdoc
- Fonte monospace "Courier New", largura 320px
- Cabeçalho dinâmico: CompanyService.GetAsync() carregado em OnInitializedAsync;
  exibe Nome + CNPJ + Endereço se preenchidos; fallback "ScaleAtacado"
- Dados do cliente buscados via CustomerService.GetByIdAsync
- Itens com preço COM acréscimo; totais: Subtotal | Desconto | TOTAL

IMPRESSÃO FÍSICA (ReceiptFormatter.cs — PrintAgent):
- Largura 40 colunas, fonte Bold 8pt, margens zeradas
- Cabeçalho dinâmico: order.CompanyName ?? "ScaleAtacado";
  exibe CNPJ e Endereço se presentes no OrderResponseDto
- Mesmos cálculos de acréscimo e totais que a prévia HTML
- PrinterName configurado em PrintAgent/appsettings.json: "EPSON TM-T20X Receipt"

GESTÃO DE USUÁRIOS
-------------------
- Senhas: PBKDF2 via ASP.NET Identity (nunca plain text)
- Admin não vê senha atual; pode apenas redefini-la via PATCH /api/user/{id}/password
- Usa GeneratePasswordResetTokenAsync + ResetPasswordAsync (sem exigir senha atual)
- Regras validadas client-side E na API:
    • Mínimo 6 caracteres  • Pelo menos uma letra minúscula (a-z)  • Pelo menos um número (0-9)
- Dialog "Alterar Senha" exibe alerta informativo sobre criptografia

INFRAESTRUTURA DE IMPRESSÃO (PrintAgent)
-----------------------------------------
PrintHub.cs: ?agentKey=xxx → grupo "PrintAgents"; demais → grupo "Clients"

API:
  GET  /api/printjob/pending       (X-Agent-Key) — jobs pendentes (failsafe ao iniciar)
  PATCH /api/printjob/{id}/status  (X-Agent-Key) — atualiza status
  GET  /api/printjob/{id}/order    (X-Agent-Key) — retorna OrderResponseDto com campos da empresa
  POST /api/order/{id}/printjob    (JWT) — cria PrintJob + SignalR "NewPrintJob" {printJobId}
  GET  /api/printjob               (JWT Admin)
Chave do agente: em appsettings.Development.json → PrintAgent:AgentKey

PrintAgent Windows (Worker Service — IMPLEMENTADO):
  Worker.cs:
    - Conecta ao SignalR Hub com ?agentKey=xxx
    - On "NewPrintJob": ProcessJobAsync(printJobId) direto (sem buscar pendentes)
    - Failsafe: ao iniciar consulta /pending e processa cada job
  ReceiptFormatter.cs:
    - 40 colunas, usa order.CompanyName/CompanyCNPJ/CompanyAddress dinâmicos
    - Acréscimo aplicado nos preços unitários e no subtotal
    - Datas em dd/MM/yyyy HH:mm (hora local)
  PrintService.cs:
    - System.Drawing.Printing (net8.0-windows)
    - Margens zeradas, Bold 8pt
  PrintApiClient.cs:
    - GetOrderForAgentAsync(printJobId), UpdateStatusAsync(printJobId, status, error?)
  appsettings.json: PrinterName: "EPSON TM-T20X Receipt"
