BUGS CORRIGIDOS (sessões anteriores)
--------------------------------------
1. Páginas em branco: ApiHttpClient.GetAsync usava GetFromJsonAsync (lança em non-2xx);
   corrigido para _http.GetAsync() + r.Content.ReadFromJsonAsync() (não lança).

2. Barra amarela (#blazor-error-ui): mesmo motivo do item 1.

3. Mixed content (HTTPS→HTTP bloqueado): ApiUrl mudou para https://7039; launch.json
   adicionou "launchProfile":"https"; CORS reordenado antes de UseHttpsRedirection.

4. Produto 400 ao criar: FluentValidation validava CompanyId != Guid.Empty mas Blazor
   envia Guid.Empty; removida a regra de CompanyId do CreateProductValidator.

5. PDV sem produtos: ProductService.GetAllActiveAsync deserializava PagedResult<T> como
   IEnumerable<T>; corrigido para ler PagedResult e retornar .Items.

6. Dialog "Novo Cliente" crash (MudOverlay duplicate section): substituído bloco
   @if + <MudOverlay> + <div posicionado> por <MudDialog @bind-Visible> padrão.
   CAUSA: MudBlazor 9 usa SectionOutlet internamente no MudOverlay; conflita com
   MudPopoverProvider já registrado no MainLayout.

7. Recibo — cálculo de Acréscimo zerado: AmountWithSurchargeTotal gravado no banco pode
   divergir do SurchargePercentage atual da forma de pagamento (se % for alterado após
   o pedido). Solução: ImprimirReciboAsync calcula tudo a partir de AmountTotal +
   SurchargePercentage (não usa AmountWithSurchargeTotal).

8. Recibo — alinhamento de itens: itens estavam em <table> rows com colspan=2; o CSS
   td:last-child{text-align:right} afetava também as linhas de colspan. Solução:
   itens convertidos para <div> com alinhamento explícito por linha; tabela de totais
   recebeu class="totais" para CSS isolado.

FLUXO COMPLETO DO PRINT AGENT
------------------------------
1. PDV finaliza pedido → API cria PrintJob (OnHoldem) → SignalR "NewPrintJob" {jobId}
2. PrintAgent recebe evento → GET /api/printjob/{jobId}/order
3. Formata recibo como texto → imprime via Windows GDI+ (System.Drawing.Printing)
4. PATCH /api/printjob/{jobId}/status → { Status: "Printed" }
5. API notifica Blazor via SignalR "PrintJobStatusChanged"
Failsafe: ao religar, PrintAgent consulta GET /pendentes e processa jobs perdidos

INSTALAÇÃO DO PRINT AGENT (quando implementado)
------------------------------------------------
1. Editar appsettings.json: ApiUrl, AgentKey, PrinterName (vazio = padrão do Windows)
2. Descobrir nome da impressora: Get-Printer | Select Name, Default
3. Registrar serviço Windows:
   New-Service -Name "ScaleAtacadoPrint" -BinaryPathName "...\ScaleAtacado.PrintAgent.exe"
               -DisplayName "ScaleAtacado - Agente de Impressão" -StartupType Automatic
   Start-Service ScaleAtacadoPrint
4. Certificado HTTPS: dotnet dev-certs https --trust

ERROS COMUNS E SOLUÇÕES
------------------------
- 401 em todas as chamadas: token expirado ou API reiniciada com nova chave.
  Solução: logout + login novamente.

- "O sistema já foi configurado": tabela Companies tem registro.
  Solução: DELETE FROM "Companies"; — NÃO basta apagar AspNetUsers.

- MudOverlay crash "already a subscriber to mud-overlay-to-popover-provider":
  Causa: MudOverlay usado diretamente; MudBlazor 9 registra SectionOutlet internamente.
  Solução: usar <MudDialog @bind-Visible> em vez de MudOverlay manual.

- Produto/Cliente com 400 sem mensagem: FluentValidation retorna ValidationProblemDetails
  (não ApiResponse), então o catch em ApiHttpClient retorna null.
  Solução: validar client-side antes de chamar a API (padrão já implementado).

- Acréscimo zerado no recibo: AmountWithSurchargeTotal no banco pode estar desatualizado.
  Solução: calcular sempre a partir de AmountTotal * (1 + SurchargePercentage/100).
