STACK
-----
- Backend  : ASP.NET Core .NET 8 — porta HTTPS 7039 / HTTP 5247
- Frontend : Blazor WebAssembly .NET 8 + MudBlazor 9.4.0 — HTTPS 7252 / HTTP 5197
- Banco    : PostgreSQL 15 (Docker, container: scale_atacado_db, porta 5432)
- ORM      : Entity Framework Core
- Auth     : JWT (Bearer) — login via /api/auth/setup (primeiro uso) ou /api/auth/login
- Impressão: SignalR PrintHub + PrintJobController (agente externo a implementar)

BUGS CORRIGIDOS NESTA SESSÃO
------------------------------
1. Páginas em branco: ApiHttpClient.GetAsync usava GetFromJsonAsync (lança em non-2xx);
   corrigido para _http.GetAsync() + r.Content.ReadFromJsonAsync() (não lança).

2. Barra amarela (#blazor-error-ui): mesmo motivo do item 1.

3. Mixed content (HTTPS→HTTP bloqueado): ApiUrl mudou para https://7039; launch.json
   adicionou "launchProfile":"https"; CORS reordenado antes de UseHttpsRedirection.

4. Produto 400 ao criar: FluentValidation validava CompanyId != Guid.Empty mas Blazor
   envia Guid.Empty; removida a regra de CompanyId do CreateProductValidator.

5. PDV sem produtos: ProductService.GetAllActiveAsync deserializava PagedResult<T> como
   IEnumerable<T>; corrigido para ler PagedResult e retornar .Items.

6. Dialog "Novo Cliente" crash (MudOverlay duplicate section): substituído bloco
   @if + <MudOverlay> + <div posicionado> por <MudDialog @bind-Visible> padrão.

7. Recibo: implementado ImprimirReciboAsync em Pedidos.razor + printRecibo(html) em
   index.html; abre nova janela com HTML formatado e dispara window.print().

RECIBO DE IMPRESSÃO (Pedidos.razor — ImprimirReciboAsync)
----------------------------------------------------------
- Busca dados completos do cliente ao abrir o pedido (ClienteService.GetByIdAsync)
- Cabeçalho: número do pedido, data, nome/CPF-CNPJ/endereço/telefone do cliente,
  forma de pagamento com % acréscimo
- Itens em 2 linhas:
    Linha 1 (esquerda, truncada com "…"): #N [CODIGO] Nome do Produto
    Linha 2 (direita, alinhada): qtd × R$ unit = R$ total → R$ totalComAcrescimo
- Rodapé: subtotal, acréscimo e TOTAL
- Função JS: window.open + setTimeout 400ms + w.print()

VALIDAÇÃO "NOVO CLIENTE" NO PDV (Pdv.razor)
--------------------------------------------
- Validação client-side antes de chamar a API (espelha o servidor):
    Nome: obrigatório, max 200
    CPF/CNPJ: obrigatório, 11 dígitos (CPF) ou 14 dígitos (CNPJ)
    Telefone: obrigatório, max 20

- Erros exibidos no campo (Error/ErrorText do MudTextField), não snackbar

ERROS COMUNS E SOLUÇÕES
------------------------
- 401 em todas as chamadas: token expirado ou API reiniciada com nova chave.
  Solução: logout + login novamente.

- "O sistema já foi configurado": tabela Companies tem registro.
  Solução: DELETE FROM "Companies"; — NÃO basta apagar AspNetUsers.

- MudOverlay crash "already a subscriber to mud-overlay-to-popover-provider":
  Causa: MudOverlay usado diretamente numa página que já tem MudPopoverProvider no layout.
  Solução: usar <MudDialog @bind-Visible> em vez de MudOverlay manual.

- Produto/Cliente com 400 sem mensagem: FluentValidation retorna ValidationProblemDetails
  (não ApiResponse), então o catch em ApiHttpClient retorna null.
  Solução: validar client-side antes de chamar a API.
